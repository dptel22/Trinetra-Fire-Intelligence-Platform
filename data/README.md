# Data — SIH 2026 PS26162

Runtime data artifacts live here. Everything except `README.md` and a
`.gitkeep` placeholder is gitignored — large binaries (parquets, DuckDB, CSVs)
are regenerated by the pipeline or pulled from the artifact store.

## Layout
```
data/
├── raw/                                        # gitignored — raw FIRMS API CSV downloads
├── processed/                                  # gitignored — pipeline output parquets
│   ├── sih2026_h3_daily_features_firms.parquet         # FIRMS-only H3-day features (serving input)
│   ├── sih2026_h3_daily_features_with_osm_wri.parquet  # + OSM/WRI static joins (serving input)
│   ├── backup_pre_2019_backfill/                       # pre-backfill snapshot — do not delete
│   └── timeline/                                       # materialized historical timeline layers
├── feature_store.duckdb                        # runtime — backend feature store (h3_daily, osm_wri_static)
├── audit_log.duckdb                            # runtime — append-only analyst audit trail
└── README.md
```

## Getting the serving parquets on a fresh clone

Either download the pinned release ZIP (SHA256-verified):

```powershell
python scripts/fetch_serving_data.py
```

or produce them from a raw FIRMS pull with `ingestion/`. Without them the
backend starts fail-closed (no predictions; `/health` reports the missing
store) and the frontend falls back to its visibly-flagged mock mode.
See [`docs/RELEASES.md`](../docs/RELEASES.md) for which release carries the
current serving snapshot.

## How the pieces connect

- `app/core/config.py` defaults point at these files:
  `H3_DAILY_PARQUET` / `OSMWRI_PARQUET` → `data/processed/*.parquet`,
  `DUCKDB_PATH` → `data/feature_store.duckdb`.
- The DuckDB feature store is seeded from the processed parquets
  (`h3_daily` ← firms parquet, `osm_wri_static` ← osm_wri parquet).
- VIIRS 7-day South Asia CSVs (`J1_VIIRS_C2_South_Asia_7d.csv`,
  `SUOMI_VIIRS_C2_South_Asia_7d.csv`) are tracked in git as small pipeline inputs;
  bulk FIRMS downloads belong in `data/raw/`.

## Data sources

- **FIRMS API**: https://firms.modaps.eosdis.nasa.gov/api/area/
- **VIIRS 375m**: SNPP (Suomi-NPP) and NOAA-20 — both ingested (the active
  pipeline does **not** ingest MODIS)
- **OSM / WRI**: static land-use and land-cover joins (see
  `notebooks/eda/osi-wri-data.ipynb`)
